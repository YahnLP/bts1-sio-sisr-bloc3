# TP – Gérer un rançongiciel (exercice de crise) et collecter des preuves

*BTS SIO SISR 1re année – Bloc 3 – S17*

> [!NOTE]
> **But.** Situation : Quand une attaque a réussi, que faire dans l'ordre, qui prévenir, et comment garder des preuves utilisables ?
>
> **Comment ce TP fonctionne.** Avant de manipuler, tu écris ce que tu **anticipes** (« J'anticipe »). Puis tu testes et tu notes ce que tu **constates**. Tu **comprends** ce que fait chaque commande (« Je comprends »). Un **bilan de compétences** clôt la séance. Les manipulations se font sur des **machines virtuelles de laboratoire**, isolées du réseau de l'établissement. Les identifiants communs d'un TP sont des **identifiants de laboratoire** : ils ne se réutilisent jamais ailleurs.

## Objectif

Gérer un rançongiciel dans un exercice de crise (qualification, premières actions, communication, décisions), puis collecter des informations volatiles sur une machine en garantissant leur intégrité et rédiger un retour d'expérience.

## Contraintes

- Groupes de 3 ou 4 pour la partie A (rôles : **responsable de crise, pilote technique, scribe, DPO/communication**), binômes pour la partie B.
- Cas **fictif** : aucune action n'est faite sur de vrais systèmes. La partie B se fait sur ta VM de laboratoire.
- Les injects de l'[annexe Delmas](annexe-cas-delmas.md) sont donnés **un par un** par l'enseignant.

## Partie B. Collecter des preuves (40 min)

Sur ta VM Debian, enregistre le script `collecte.sh` :

```bash
#!/bin/bash
# Collecte des informations volatiles (laboratoire), dans l'ordre de volatilité
set -u
DEST=~/preuves/$(hostname)-$(date +%Y%m%d-%H%M%S)
mkdir -p "$DEST" && cd "$DEST" || exit 1
{
  date --iso-8601=seconds; echo "Opérateur : $(whoami)"; echo "Machine : $(hostname)"
} > 00-contexte.txt
uptime                          > 01-uptime.txt
ss -tupan                       > 02-connexions.txt 2>&1
ps -eo pid,ppid,user,lstart,cmd --sort=start_time > 03-processus.txt
who -a                          > 04-sessions.txt
last -n 30                      > 05-dernieres-connexions.txt 2>&1
journalctl --no-pager -n 500    > 06-journal-systeme.txt 2>&1
ls -la /tmp /var/tmp            > 07-fichiers-tmp.txt 2>&1
sha256sum ./*.txt               > SHA256SUMS
echo "Collecte terminée dans $DEST"
```

```bash
chmod 750 collecte.sh
sudo ./collecte.sh
ls ~/preuves/*/
cd ~/preuves/*/ && sha256sum -c SHA256SUMS
```

Falsifie volontairement une pièce, puis revérifie :

```bash
echo "modification" >> 05-dernieres-connexions.txt
sha256sum -c SHA256SUMS
```

**Je comprends.**

| Élément | Rôle |
|---|---|
| Ordre des fichiers `01`, `02`… | Du plus volatil (état du système, connexions) au moins volatil |
| `ss -tupan` | Connexions réseau avec les processus |
| `ps -eo … lstart` | Processus avec leur **date de démarrage** (repérer un processus récent suspect) |
| `who -a`, `last` | Sessions en cours et récentes |
| `sha256sum … > SHA256SUMS` | **Empreintes** pour prouver l'intégrité |
| `sha256sum -c` | Vérifie qu'aucun fichier n'a changé |
