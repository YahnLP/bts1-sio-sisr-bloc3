# TP – Scanner un réseau de laboratoire, interpréter les résultats et rédiger une fiche d'audit

*BTS SIO SISR 1re année – Bloc 3 – S16*

> [!NOTE]
> **But.** Situation : Comment trouver les failles d'un système avant un attaquant, dans le cadre de la loi, et décider quoi corriger en premier ?
>
> **Comment ce TP fonctionne.** Avant de manipuler, tu écris ce que tu **anticipes** (« J'anticipe »). Puis tu testes et tu notes ce que tu **constates**. Tu **comprends** ce que fait chaque commande (« Je comprends »). Un **bilan de compétences** clôt la séance. Les manipulations se font sur des **machines virtuelles de laboratoire**, isolées du réseau de l'établissement. Les identifiants communs d'un TP sont des **identifiants de laboratoire** : ils ne se réutilisent jamais ailleurs.

## Objectif

Rédiger une autorisation d'audit, scanner un réseau de laboratoire avec Nmap, interpréter un résultat de scan, prioriser les vulnérabilités et rédiger une fiche d'audit avec un plan de remédiation.

## Contraintes

- Binôme, durée : 3 h 20.
- **Les scans ne se font que sur le réseau de laboratoire isolé** (VM `adm` et `srv`), avec l'accord de l'enseignant. **Jamais** sur Internet, sur le réseau de l'établissement ni sur les machines d'autres groupes.
- Les rapports ne contiennent aucune donnée personnelle réelle.

## Partie B. Scanner le laboratoire (70 min)

### B1. Préparer la cible

Sur `srv`, installe quelques services volontairement présents (sur un réseau isolé) :

```bash
sudo apt install -y nginx vsftpd
sudo sed -i 's/^anonymous_enable=.*/anonymous_enable=YES/' /etc/vsftpd.conf
sudo systemctl restart vsftpd nginx
ss -tlnp
```

> [!WARNING]
> Le FTP anonyme est une **mauvaise configuration de laboratoire** : à supprimer en fin de séance (`sudo apt purge -y vsftpd`).

### B2. Scanner depuis `adm`

```bash
sudo apt install -y nmap
mkdir -p ~/audit && cd ~/audit
nmap -sn 192.168.56.0/24 -oN 1-decouverte.txt
nmap -sS -p- 192.168.56.10 -oN 2-ports.txt
nmap -sV -p 21,22,80 192.168.56.10 -oN 3-services.txt
nmap --script ftp-anon -p 21 192.168.56.10 -oN 4-ftp.txt
cat 3-services.txt
```

**Je comprends.**

| Option | Rôle |
|---|---|
| `-sn` | **Découverte** seulement : quelles machines répondent (pas de scan de ports) |
| `-sS` | Scan **SYN** (demi-connexion) |
| `-p-` | **Tous** les ports (1 à 65535) |
| `-sV` | Détection des **services et versions** |
| `--script ftp-anon` | Script qui teste la connexion FTP **anonyme** |
| `-oN fichier` | Sauvegarde en texte : sert de **preuve** dans le rapport |

**J'anticipe.** Quels ports penses-tu trouver ouverts sur `srv` ? Y aura-t-il un état « filtered » si le pare-feu de S14 est actif ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Ouverts : 21 (FTP), 22 (SSH, si le pare-feu l'autorise depuis `adm`), 80 (web). Avec le pare-feu de S14 en refus par défaut, les autres ports apparaissent **filtered** (silence) ; sans pare-feu, **closed**.

</details>
