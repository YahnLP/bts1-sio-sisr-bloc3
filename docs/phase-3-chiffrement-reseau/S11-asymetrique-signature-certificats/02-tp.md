*BTS SIO SISR 1re année – Bloc 3 – S11*

> [!NOTE]

>

## Objectif

Générer une paire de clés, chiffrer une clé de session avec une clé publique (chiffrement hybride), signer et vérifier un fichier, observer un échange de clés, puis lire un certificat X.509.

## Contraintes

- Binôme, durée : 3 h 20.
- Dossier de travail : `mkdir -p ~/asym && cd ~/asym`.
- Les clés de ce TP sont des **clés de laboratoire** : on ne les réutilise jamais ailleurs. La clé **privée** (`alice.key`) reste dans ton dossier ; ne l'envoie à personne.

## Partie A. Paire de clés et chiffrement hybride (50 min)

### A1. Générer la paire

```bash
cd ~/asym
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out alice.key
openssl pkey -in alice.key -pubout -out alice.pub
chmod 600 alice.key
head -2 alice.key
cat alice.pub
openssl pkey -in alice.pub -pubin -text -noout | head -3
```

**Je comprends.**

| Commande | Rôle |
|---|---|
| `genpkey -algorithm RSA …3072` | Génère une clé **privée** RSA de 3072 bits |
| `pkey -in … -pubout` | Extrait la clé **publique** de la clé privée |
| `chmod 600` | Seul le propriétaire peut lire la clé privée |
| `-----BEGIN … KEY-----` | Format **PEM** : données en base 64 entre deux lignes d'en-tête |

**Questions.**

1. Quelle clé peut être publiée sur un site web ? Laquelle ne doit jamais quitter ton poste ? ______________________
2. Que signifie `chmod 600` pour la clé privée ? ______________________

### A2. Essayer de chiffrer directement avec RSA

```bash
echo "Message pour Alice" > msg.txt
openssl pkeyutl -encrypt -pubin -inkey alice.pub -pkeyopt rsa_padding_mode:oaep -in msg.txt -out msg.rsa
wc -c msg.rsa
openssl pkeyutl -decrypt -inkey alice.key -pkeyopt rsa_padding_mode:oaep -in msg.rsa
head -c 500 /dev/zero | tr '\0' 'a' > long.txt
openssl pkeyutl -encrypt -pubin -inkey alice.pub -pkeyopt rsa_padding_mode:oaep -in long.txt -out long.rsa
```

**J'anticipe.** Le chiffrement du fichier `long.txt` (500 caractères) va-t-il fonctionner ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

**Non** : RSA ne chiffre que des données **plus petites que la clé** (moins de 384 octets, moins le remplissage OAEP). Pour un fichier, on utilise le chiffrement **hybride**.

</details>

3. Quelle taille a `msg.rsa` ? Quel rapport avec la taille de la clé ? ______________________
4. Quelle est l'erreur obtenue pour `long.txt` ? ______________________

### A3. Chiffrement hybride

```bash
head -c 2000 /dev/urandom | base64 > gros.txt
openssl rand -hex 32 > session.key
openssl enc -aes-256-cbc -pbkdf2 -in gros.txt -out gros.enc -pass file:session.key
openssl pkeyutl -encrypt -pubin -inkey alice.pub -pkeyopt rsa_padding_mode:oaep -in session.key -out session.key.rsa
rm session.key
ls -l gros.enc session.key.rsa
```

Alice (qui détient `alice.key`) déchiffre :

```bash
openssl pkeyutl -decrypt -inkey alice.key -pkeyopt rsa_padding_mode:oaep -in session.key.rsa -out session.recup
openssl enc -d -aes-256-cbc -pbkdf2 -in gros.enc -pass file:session.recup | cmp - gros.txt && echo "identique"
```

5. Que contient `session.key.rsa` ? Pourquoi supprime-t-on `session.key` ? ______________________
6. Qui peut déchiffrer `gros.enc` : toute personne qui a `alice.pub` ? ______________________
7. Quel algorithme chiffre le **gros fichier** ? Lequel chiffre la **clé** ? Pourquoi les deux ? ______________________
8. Cite deux protocoles ou outils qui fonctionnent sur ce principe hybride. ______________________

## Partie B. Signer et vérifier (40 min)

```bash
cd ~/asym
echo "Virement de 1000 euros à Dupont" > ordre.txt
openssl dgst -sha256 -sign alice.key -out ordre.sig ordre.txt
openssl dgst -sha256 -verify alice.pub -signature ordre.sig ordre.txt
echo "Virement de 9000 euros à Dupont" > ordre-falsifie.txt
openssl dgst -sha256 -verify alice.pub -signature ordre.sig ordre-falsifie.txt
```

**J'anticipe.** La vérification de `ordre-falsifie.txt` avec la signature de `ordre.txt` réussira-t-elle ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

**Non** : la signature est calculée sur l'**empreinte** du document. Si le document change, l'empreinte change et la vérification échoue (`Verification failure`).

</details>

**Je comprends.**

| Élément | Rôle |
|---|---|
| `dgst -sha256 -sign alice.key` | Calcule l'empreinte SHA-256 puis la **signe** avec la clé **privée** |
| `-verify alice.pub -signature …` | **Vérifie** avec la clé **publique** |
| `Verified OK` / `Verification failure` | Résultat de la vérification |

**Questions.**

10. Quelles garanties apporte la signature que le HMAC de S10 n'apportait pas ? ______________________
11. Pourquoi cette vérification n'est-elle utile que si l'on est sûr que `alice.pub` appartient à Alice ? ______________________
12. Une signature empêche-t-elle de **lire** le document ? ______________________

## Partie C. Échanger un secret avec Diffie-Hellman (30 min)

Avec la courbe X25519, Alice et Bob fabriquent le **même secret** sans jamais l'envoyer :

```bash
cd ~/asym
openssl genpkey -algorithm X25519 -out a.key
openssl genpkey -algorithm X25519 -out b.key
openssl pkey -in a.key -pubout -out a.pub
openssl pkey -in b.key -pubout -out b.pub
openssl pkeyutl -derive -inkey a.key -peerkey b.pub -hexdump
openssl pkeyutl -derive -inkey b.key -peerkey a.pub -hexdump
```

13. Les deux secrets calculés sont-ils identiques ? Qui a eu besoin de la clé privée de l'autre ? ______________________
14. Ce qui a circulé entre Alice et Bob, ce sont `a.pub` et `b.pub`. Un espion qui les lit peut-il calculer le secret ? ______________________
15. Pourquoi cet échange n'**authentifie**-t-il pas Bob ? Quelle attaque cela permet-il ? ______________________
16. Que signifie *éphémère* dans ECDHE, et quel avantage cela donne-t-il ? ______________________

### D2. Dans le terminal

Génère un certificat **auto-signé** de laboratoire et lis-le :

```bash
cd ~/asym
openssl req -x509 -newkey rsa:2048 -nodes -keyout srv.key -out srv.crt -days 30 \
  -subj "/C=FR/O=Lab SISR/CN=srv.lab.local" \
  -addext "subjectAltName=DNS:srv.lab.local,DNS:www.lab.local"
openssl x509 -in srv.crt -noout -subject -issuer -dates -serial
openssl x509 -in srv.crt -noout -ext subjectAltName,basicConstraints
openssl x509 -in srv.crt -noout -fingerprint -sha256
```

**Je comprends.**

| Élément | Rôle |
|---|---|
| `req -x509` | Crée directement un certificat **auto-signé** |
| `-nodes` | Pas de mot de passe sur la clé privée (laboratoire seulement) |
| `-subj "/C=…/O=…/CN=…"` | Identité du sujet (pays, organisation, nom courant) |
| `-addext subjectAltName=…` | Noms de domaine valables : c'est ce que **vérifie** le navigateur |
| `x509 -noout -subject -issuer -dates` | Affiche sujet, émetteur et validité |
