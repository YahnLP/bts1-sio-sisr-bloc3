## Objectif

Définir les objectifs de reprise d'une entreprise, concevoir une stratégie de sauvegarde dans un budget, la mettre en œuvre avec un outil chiffré, **détruire** puis **restaurer** pour prouver qu'elle fonctionne, et chiffrer un support amovible.

## Partie B. Sauvegarder, détruire, restaurer (60 min)

On utilise **restic**, un outil de sauvegarde libre qui **chiffre** et **déduplique**.

```bash
mkdir -p ~/donnees ~/depot-sauvegarde ~/restauration
for i in 1 2 3; do echo "contrat client $i" > ~/donnees/contrat$i.txt; done
export RESTIC_PASSWORD='Lab-restic-2026'
restic init --repo ~/depot-sauvegarde
restic -r ~/depot-sauvegarde backup ~/donnees
restic -r ~/depot-sauvegarde snapshots
```

**Je comprends.**

| Commande | Ce qu'elle fait |
|---|---|
| `export RESTIC_PASSWORD=...` | Donne le mot de passe du dépôt à restic (identifiant de laboratoire) |
| `restic init --repo` | Crée un dépôt **chiffré** par ce mot de passe |
| `restic -r ... backup dossier` | Sauvegarde le dossier ; seuls les **morceaux nouveaux** sont stockés |
| `restic -r ... snapshots` | Liste les sauvegardes (instantanés de restic) : date, identifiant |

**J'anticipe.** Si je modifie un seul fichier et que je relance la sauvegarde, restic va-t-il recopier les trois fichiers ? Que dit-il à la fin ? ______________________

```bash
echo "contrat client 1, avenant" >> ~/donnees/contrat1.txt
restic -r ~/depot-sauvegarde backup ~/donnees
```

<details markdown="1">
<summary>Éléments de réponse</summary>

Non : restic compare le contenu et ne **stocke que les différences**. Le résumé indique un fichier modifié et très peu de données ajoutées.

</details>

### Simuler l'incident

```bash
rm -rf ~/donnees/*
ls ~/donnees
restic -r ~/depot-sauvegarde restore latest --target ~/restauration
ls ~/restauration/home/*/donnees 2>/dev/null || find ~/restauration -name 'contrat*'
restic -r ~/depot-sauvegarde check
```

**Je comprends.** `restore latest --target` remet le dernier instantané dans un dossier **séparé** (on ne restaure jamais par-dessus sans réfléchir) ; `check` **vérifie l'intégrité** du dépôt : c'est la preuve que la sauvegarde est lisible.

### Attaquer la sauvegarde elle-même

Un rançongiciel détruit aussi les sauvegardes qu'il atteint. Fais d'abord une **copie séparée** (celle qui, en vrai, serait hors ligne), puis détruis le dépôt :

```bash
sudo mkdir -p /mnt/copie-hors-ligne
sudo rsync -a ~/depot-sauvegarde/ /mnt/copie-hors-ligne/depot/
rm -rf ~/depot-sauvegarde
restic -r ~/depot-sauvegarde snapshots
restic -r /mnt/copie-hors-ligne/depot snapshots
```

**J'anticipe.** Que donnent les deux dernières commandes ? Que démontre cette expérience ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

La première échoue (dépôt détruit) ; la seconde liste encore les instantanés : la **copie séparée** a survécu. Une sauvegarde qui reste **accessible en écriture** depuis le système attaqué peut être détruite avec lui : d'où la copie **hors ligne ou immuable** de la règle 3-2-1-1-0.

</details>

**Question.** Ici le répertoire `/mnt/copie-hors-ligne` est sur la même machine : en quoi cette copie ne répond-elle **pas** complètement à la règle 3-2-1 ? ______________________

### Gérer la rétention

```bash
restic -r /mnt/copie-hors-ligne/depot forget --keep-daily 7 --keep-weekly 4 --keep-monthly 12 --dry-run
```

**Je comprends.** `forget` applique une **politique de rétention** (7 quotidiennes, 4 hebdomadaires, 12 mensuelles) ; `--dry-run` **simule** sans rien supprimer : toujours simuler avant de supprimer des sauvegardes.

## Partie C. Chiffrer un support (30 min)

Sans clé USB, on simule un support avec un **fichier de 100 Mo** chiffré par **LUKS**.

```bash
fallocate -l 100M ~/support.img
sudo cryptsetup luksFormat ~/support.img
sudo cryptsetup open ~/support.img coffre
sudo mkfs.ext4 /dev/mapper/coffre
sudo mkdir -p /mnt/coffre && sudo mount /dev/mapper/coffre /mnt/coffre
echo "document confidentiel" | sudo tee /mnt/coffre/secret.txt
sudo umount /mnt/coffre && sudo cryptsetup close coffre
```

**Je comprends.**

| Commande | Ce qu'elle fait |
|---|---|
| `fallocate -l 100M` | Crée un fichier de 100 Mo qui servira de « disque » |
| `cryptsetup luksFormat` | Prépare le support avec **LUKS** et demande une phrase de passe (identifiant de laboratoire) |
| `cryptsetup open ... coffre` | Déverrouille le support : il apparaît comme `/dev/mapper/coffre` |
| `mkfs.ext4`, `mount` | Crée un système de fichiers et le monte pour l'utiliser |
| `umount`, `cryptsetup close` | Ferme : les données redeviennent illisibles |

**J'anticipe.** Si j'ouvre `~/support.img` avec un éditeur hexadécimal (`xxd ~/support.img \| head`), verrai-je « document confidentiel » en clair ? ______________________

```bash
xxd ~/support.img | grep -i confidentiel || echo "texte non trouvé"
```

<details markdown="1">
<summary>Éléments de réponse</summary>

Non : le contenu est **chiffré** (« texte non trouvé »). Sans la phrase de passe, un support perdu ou volé ne livre rien.

</details>

**Question.** Quelle est la conséquence de la perte de la phrase de passe LUKS ? Où conserver une copie de secours de la phrase de passe, et comment la protéger ? ______________________
